# 实时消息展示进度

## 行为

- 保持原有发送间隔、预热、账号 fetch/WSS、访客 WSS 和最终统计规则。
- 访客收包时通过不消费原队列的订阅，将回执与当前任务关联。HTTP 响应返回消息 ID 前收到的弹幕会在有限缓存内等待匹配。
- 按任务所属房间、发送账号身份、消息 ID、内容和本地发送起始时间确认。不依据 HTTP 200 或接口接受直接宣称展示成功。
- 确认后立即打印一次“消息成功展示”，更新展示计数；不等待整批发送结束。不在 WSS 线程直接操作 Qt 控件，继续使用原来的进度回调和 Qt 信号。
- 表格运行中显示“已发 4/10 · 展示 3/10”。已发按返回消息请求结果的逻辑消息条数计数，重试不重复计数；初始化异常不计为已发。
- 同一消息 ID 不可确认两个逻辑消息，任务结束清理订阅。超时临界点在同一锁内协调收包证据与结果封存，避免同时归为展示成功和未观察到。

## 逐条超时日志与默认次数（后续修订）

每条消息接口返回后，独立开始观察计时。到达设置的观察时长仍未匹配到弹幕，即打印该条消息的“监听期内未发现实际弹幕”，不等待整批消息全部发送完成。整批核对时不重复打印同一观察窗口的结果，也不重新等待一整个观察窗口。

该提示只表示截止到该观察窗口没有证据，不是断言消息永远不可见。任务仍在运行且尚未封存该条结果时，如果后来收到真实回执，仍立即记录展示成功，以实际证据为准。用户取消或监听已不可用时，不将其误报为完整观察窗口内未展示。

默认总尝试次数改为 1，不自动重发；用户可在工具内自行修改，已有保存设置不覆盖。此项是消息接口次数，不改变账号 fetch 或监听连接各自的重试配置。

## 封禁及禁言说明

服务端明确提示账号封禁时分类为 `account_banned`；已知禁言响应分类为 `account_silenced`。两者停止该账号在对应房间的后续消息，不重试该限制响应，其他账号继续。

面板立即记录限制原因并显示红色标记，分房间详情保留分类。网络超时、普通 403、评论含违禁词、未观察到弹幕均不自动推断为账号封禁。

这不是对所有未知服务端状态码的封禁识别保证，也不永久修改账号保存状态，避免把房间级禁言当成全平台账号失效。
