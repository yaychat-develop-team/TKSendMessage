# 多直播间并发发送与发送设置布局

状态：已按用户确认方案实现并经独立审查；最终 383 项回归、布局预览、包内核对及空账号 EXE 启动检查通过，发布到 dist/TKChatWave.exe。未进行真实直播间发送测试。

## 目标与范围

用户希望发送次数、发送间隔不再挤在消息框右侧，并通过目标用户名中的 `;` 一次指定多个直播间，多个直播间同时发送。保留现有账号选择、每账号发送次数、发送间隔、WSS 预热及展示确认功能。

登录浏览器清理修复、登录结果日志、WSS 用途标识及响应日志前 150 个字符属于此前已验证的基线，不在本次重新设计。

## 界面与输入

- 目标用户名独占一行，示例占位符为 `主播A;主播B;主播C`。
- 消息内容框占满下一行，保持可编辑高度。
- 消息框下方设置一排左对齐控件：每账号每直播间发送次数、发送间隔。窄窗口下也不挤压消息框。
- 次数范围沿用 1–100、默认 1；间隔沿用 0.1–3600 秒、默认 1 秒。
- 支持半角 `;` 及全角 `；`。去除两端空白和前导 `@`、忽略空项、按不区分大小写去重并保留首次出现的顺序。
- 只接收用户名，不接收 URL、路径或含空白的用户名。无有效目标或任一非空目标格式无效时，整体拒绝启动并提示，不产生网络发送。

## 并发调度

- 最多 **3 个直播间同时运行**，超过的直播间进入队列；一个房间的全部账号完成后释放房间名额，不新增复杂设置。
- 每个运行中的直播间内，所有勾选的本地账号并发执行，不按账号排队；单直播间也使用账号并发。不同直播间可以同时使用同一已选账号，各自维护连接。账号过多会增加本机连接和线程资源占用，不暗中改变用户指定的次数或间隔。
- 次数按“账号 × 直播间”分别计算。例如 2 个账号、3 个直播间、次数 3，最多产生 18 次发送请求，不因未观察到展示自动加发。
- 每个直播间的每个账号独立完成至少 30 秒预热、至少 3 次心跳；其连接贯穿该账号的连续发送及展示确认。同一房间账号间不共享登录态 WSS。
- 各“房间 × 账号”任务并行预热，各自满足条件后开始发送，不要求所有任务在同一毫秒发出请求。
- 一个房间不存在、未开播或失败，只影响该房间；单账号失败也不停止同房间其他账号。所有账号或所有房间均失败时，总状态明确失败，不误报全部成功。
- 停止按钮通过共享取消事件阻止队列中新任务启动；正在进行的任务沿用现有协作取消，在安全边界停止，不强杀线程。

## 账号、报告与日志隔离

- 并发任务不直接竞争写入正式账号文件。启动前准备一次账号及环境种子快照；每个“房间 × 账号”任务使用仅包含本账号的私有副本，存放在本机 runtime 的独立临时目录，任务结束后清理。
- 正式账号状态由协调层统一收尾。只合并确有变化且正式记录仍与启动快照一致的记录；确认失效账号优先移除。用户或其他进程已修改的记录不被旧快照覆盖。
- 每个“房间 × 账号”的失败、禁言报告独立存放在本次运行报告目录中，避免互相覆盖；总摘要记录房间、账号与完成状态。报告目录使用内部生成的安全标识，不将未经校验的用户名作为路径。
- 日志始终标明直播间，保留 `delivery_observer` / `account_heartbeat` 连接用途和前 150 字脱敏响应预览。不打印账号副本内容、Cookie、签名或完整带查询参数 WSS 地址。
- 每条已实际发出的消息都打印直播间用户名、账号用户名及短 ID、消息序号、请求结果、消息 ID（如有）和展示核对结果。展示结果区分“已观察到展示”“未观察到”“监听不可用”“发送失败”；未观察到不表述为确定未显示。账号无用户名时用短 ID 代替，不隐藏归属。日志不依赖完整响应体中的账号信息，因此响应仅打印前 150 字也不会丢失归属信息。
- 总统计使用每个“房间 × 账号”任务的最新累计快照求和，不重复累加进度回调；结束时给出每房间每账号的请求成功、确认展示、未观察到、失败计数。

## 工程边界

- `desktop/main_window.py`：布局、输入提示、进度与完成状态。
- 独立的目标解析、并发协调和账号快照模块：解析校验、房间队列、账号并发、私有快照、取消、状态合并及汇总。
- `desktop/workers.py`：在现有 Qt 工作线程中调用协调层，保留单直播间兼容行为。
- 日志接收层：从任务上下文读取直播间标识，确保并发日志不串房间。
- 原有单直播间 runner 的发送及消息 ID 展示核对逻辑尽量保持不变；补上逐条明确展示结果日志。CLI 单直播间调用保持兼容。

## 验收

- 自动测试解析、去重、无效目标零发送；验证三个房间真正重叠运行、第四个排队，以及同房间多个账号重叠运行、停止、单账号与单房间失败隔离。
- 验证账号快照隔离、并发报告不覆盖、失效账号收尾、外部更新不被旧快照覆盖，以及累计统计不重复计数。
- 验证每账号每房间的次数与间隔、30 秒/3 心跳门槛、发送期间 WSS 保持连接及按消息 ID 核对。
- 验证已展示、未观察到、监听不可用、请求失败、无账号用户名、取消后已完成请求等路径的逐条结果归属；并发日志不得串账号或串直播间。
- Qt 测试检查控件位于消息框下方、对齐、可访问名称及忙碌时禁用；在常用和窄窗口尺寸做布局预览检查。
- 测试使用受控替身，不额外向真实直播间发送消息；真实发送需用户另行指定测试范围。
- 全套回归通过后，以干净源码构建 EXE，执行无账号启动检查、包内源码与隐私核对，保留正式 runtime 和旧 EXE 备份。
