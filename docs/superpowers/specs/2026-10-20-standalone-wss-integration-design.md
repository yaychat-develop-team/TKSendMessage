## 模块与接口

在 `tiktok_live/wss/` 内分离以下职责，避免把全部逻辑堆入 `listen_msg.py`：

- 协议与签名：从独立脚本提取纯函数，保留来源说明、随机源可注入和字节级对照测试；不读账号、不执行 JS、不发网络请求。
- 会话准备：访客入口创建全新内存 CookieJar，按脚本白名单提取访客 Cookie；账号入口仅接收任务传入的本账号 Cookie/UA，不接收其他账号或访客 jar。
- 连接传输：单连接独立持有握手、socket、心跳记录、入房响应、取消标志和收尾状态；支持现有系统 HTTP CONNECT 代理，不更改系统代理或 TLS 校验。

`listen_msg.py` 仍提供 `LiveMessageListener`、`ObservedComment`、`start`、`close`、`available`、`error`、`room_id`、`record_comment`、`wait_for_comment` 的业务能力，事件不再暴露 TikTokLive 类型。心跳层改读明确的连接状态和证据接口，不伪造 `_client._ws` 兼容对象。

保留原有任务上下文传播，使连接线程的日志带有直播间、发送账号及连接用途。现有 runner 的已完成结果保留、取消和隔离存储合并语义不变。

## Cookie 与目的地隔离

`websocket-client==1.7.0` 的默认握手会合并并更新模块级 CookieJar。新传输必须使用自有逐连接握手适配，复用所需的 socket/帧传输能力，但不能走共享 CookieJar 的默认握手路径。禁止靠临时清空全局 jar、全局 monkeypatch 或把整个收包循环串行加锁来解决污染。

握手只发送本连接显式 Cookie；响应中的 Set-Cookie 不进入全局缓存，不传播给其他连接。访客链路拒绝出现登录 Cookie，不能因匿名准备失败而读取账号库兜底。账号 Cookie 不发给匿名 HTTP 初始化、第三方签名服务或代理认证字段，也不进入进程参数、异常详情或日志。

WSS 只允许经过校验的 TikTok 直播域名、`wss`、443/默认端口及直播协议路径；目标 room ID 必须与任务一致。禁止 URL 用户密码、重定向、TLS 校验关闭和任意可配置请求头注入。HTTP 公开页面请求同样限制来源并禁止重定向。连接前完成检查，再使用认证材料。

逐连接握手适配必须验证 HTTP 101、Upgrade/Connection 和 Sec-WebSocket-Accept，限制握手响应大小；非 101 不能当作已连接。若复用库内部实现或代码，固定依赖版本并保留所需许可声明。

## 心跳和生命周期

每个账号 × 房间独立维护账号连接，覆盖连续发送和展示确认阶段。30 秒预热、至少三次目标房间实际发送成功的心跳、既有心跳间距及有效服务端入房响应门槛不降低。只在底层发送成功后增加心跳计数，不能用定时器 tick 或本地构造的入房包代替服务端证据。

心跳按单调时钟独立调度，空闲、接收超时和高频业务帧均不能饿死心跳。只 ACK 服务端要求的当前 log ID/internal extension。连接或心跳失效后阻止后续消息请求；不后台重连并自动续发。

连接生命周期由桌面任务持有，不沿用 CLI 的 600 秒、1000 条聊天、10000 帧或固定总发送预算作为任务自动结束条件。保留逐帧、解压后大小、字段数量、评论去重缓存和队列的有界限制，防止无限内存增长或解压炸弹。

接收处理二进制、分片、ping/pong、close、ACK、未知事件和畸形输入。`available` 不能只表示线程已启动。启动有超时，停止会关闭本连接并唤醒等待者；线程真正退出前不销毁其所有者，不能遗留后台重连或抢占其他账号资源。

## 展示确认和日志

访客连接收到的聊天事件归一化为消息 ID、发送者数字 ID/用户名/昵称、正文、房间 ID和接收时间。保留大整数 ID 的字符串精度。按当前任务的发送结果 ID、时间、正文及发送者身份联合核对；历史弹幕或相同正文的其他用户消息不能算成功。

逐条保留 `observed`、`not_observed`、`listener_unavailable`、`send_failed` 等现有结果，包含账号短 ID、用户名、房间和消息序号。不为未发出的队列伪造发送结果，不把“未监听到”说成“确定未展示”。账号心跳成功也不等于服务器已验证账号身份或消息一定可见。

日志明确区分两种连接用途，保留连接开始/成功/失败/关闭、预热和心跳信息。只打印安全的域名/路径、错误类型或预定义原因，不输出完整查询参数、Cookie、签名、原始帧或代理凭据。HTTP 响应预览继续先脱敏再截取前 150 字符。

## 测试边界与验收

延续不联网、不读取真实账号的验证边界；“继续”确认接入设计，不自动授权真实直播间发送。需要平台连通性或实发验收时，另行确认测试房间、账号、次数和时长，不从历史消息自行挑选账号进行发送。

必须完成：

1. 协议/签名对照、gzip/超长/畸形帧、入房/心跳/ACK、分片、ping/pong/close 的离线测试。
2. 合成握手证明登录连接只携带本账号 Cookie、访客连接只携带自己的访客 Cookie；两个账号、多个房间、服务端 Set-Cookie 和错误收尾不串状态。
3. 通过受控本机对端验证实际握手和帧传输，不只模拟高级客户端；对端不访问外网、不使用真实认证材料。
4. 受控时钟与发送边界验证 30 秒/三心跳/入房门槛、发送期间连接存活、心跳失败、取消和线程收尾。
5. 回归多房间/多账号并发、消息次数和间隔、逐条展示匹配、账号状态合并、登录关闭和日志脱敏。
6. 干净副本完整测试、禁用旧库的导入和启动检查、源码/浏览器隐私扫描、候选 EXE 构建、冻结程序启动和包内依赖核对。

离线通过只能证明实现和隔离行为，不能作为平台接受登录态连接或弹幕实际展示的证据。交付说明必须区分实测与未实测范围。
