# 使用 TiktokApis 协议替换 TikTokLive

状态：用户已确认设计，并在编写计划时追加“Node 代码改成 Python”。本文已据此改为纯 Python 签名方案，与实施计划一起待审阅。尚未修改产品代码、安装依赖、发起直播间连接或重新打包。

## 目标与确认范围

用户要求使用 https://github.com/cv-cat/TiktokApis 的直播 WSS 实现，替换当前工具依赖 TikTokLive 的全部监听和心跳。

用户随后明确：发送心跳需要登录态。对“登录接口”的理解已在会话中确认成“当前发送账号的登录 Cookie”。最终边界是：

- 展示监听 `delivery_observer`：独立匿名会话，不读取、传入或继承本地发送账号的 Cookie、storage、profile 或认证材料。
- 账号心跳 `account_heartbeat`：携带当前发送账号的登录 Cookie 和匹配的 UA；不同账号、不同直播间连接完全隔离。
- HTTP 消息发送继续使用现有登录态、签名和请求流程，本次不迁移到上游的聊天发送接口。
- 产品运行、测试替身和构建配置均不再依赖 TikTokLive；不保留自动回退到旧实现的路径。
- WSS 签名与协议逻辑用 Python 实现，不包含 Node 运行时，不通过 subprocess、内嵌 JS 引擎或调用浏览器 frontierSign 代替 Python 算法迁移。
- 保留最多三个直播间并发、房间内所有已选账号并发、发送次数/间隔、停止收尾、状态合并、逐条展示核对及现有界面布局。

“匿名”是无需用户提供登录 Cookie、不使用发送账号认证材料；允许匿名会话自动获得自己的临时访客 Cookie 和签名参数，并不承诺服务器无需任何访客状态即可连接。匿名连接不能用于证明发送账号在线。

## 当前代码与上游事实

当前 `listen_msg.py` 通过 TikTokLiveClient 接收事件，向 runner 提供 `start`、`close`、`available`、`error`、`room_id` 和 `wait_for_comment`。`tiktok_live/heartbeat_socket.py` 还依赖 TikTokLive 的连接与 protobuf 类型；`heartbeat.py` 读取连接私有属性来检查就绪状态。依赖同时进入 requirements、打包 spec 和 app 启动自检，不能只替换一个 import。

上游不是现成的无 Cookie 通用监听器：

- `api/tiktok_web.py` 的 `iter_live_ws_events` 使用 auth、浏览器环境、初始 protobuf fetch 和本地 frontier 签名，并把该会话 Cookie 传给 WSS。
- `builder/auth.py` 的浏览器环境校验要求访客字段和设备/令牌证据；不能简单传空字符串并忽略校验。
- `signing/live_wire.py` 实现 PushFrame、gzip LiveResponse、聊天事件、心跳、入房及 ACK 的相关编解码。
- 上游 README 说明 WSS 本地签名依赖 Node.js；整体库还声明 Python 3.11+。本工具现有 Python 3.10，因此不整体安装上游库、不顺带升级所有发送依赖。上游 JS 签名必须另行迁移并验证，不能把移除 Node 的依赖声明当成算法已完成。

## 方案选择

采用“只适配直播 WSS 相关部分”：本地协议模块、会话准备、签名运行器和传输层，外部仍维持当前工具的监听/心跳接口。这样可保留现有发送与并发架构，避免引入上游 Creator、私信、电商等无关功能。

不采用整体引入上游 API facade：其认证环境、Python 版本及大量无关接口会扩大升级范围。也不保留 TikTokLive 作为兼容后备，因为这与用户确认的彻底移除相矛盾。

## 模块边界

新实现放在 `tiktok_live/wss/` 下，职责分开：

- `protocol.py`：仅处理字节协议、事件归一化、入房/心跳/ACK 编解码，不读账号、不发 HTTP。
- `bootstrap.py`：准备房间信息、游标和对应会话的环境。分别提供匿名会话及账号会话入口，禁止用同一个共享 cookie jar。
- `signer.py`：调用本地纯 Python frontier 签名算法，使用当前会话输入生成签名；不请求第三方签名服务，不复用抓包的固定签名。
- `transport.py`：管理单连接的 WSS 生命周期、定时心跳、ACK、错误与取消，把收到的事件交给调用方。
- `tiktok_live/algorithms/frontier.py` 保存迁移后的 Python 算法；默认测试使用已脱敏的合成输入及固定对照向量，不需要 JS/SDK 运行时。开发阶段可以把固定版本原 SDK 作为独立对照，但不能进入正式运行或默认测试依赖。

纯 Python 签名是前置验收门槛：固定时钟与随机源后，结果必须与原算法逐字节一致，并覆盖输入及运行状态变化；只证明长度为 16 不算实现成功。如果不能建立可信对照或完成迁移，停止后续替换并说明未完成，不回退到 JS 引擎、Node、第三方签名站点或伪造常量，不发布不可用候选包。

`listen_msg.py` 负责兼容现有 `LiveMessageListener`/`ObservedComment` 公共行为、线程边界和评论匹配；不再暴露 TikTokLive 事件对象。

`tiktok_live/heartbeat_socket.py` 保留连接目的地校验和心跳证据的职责，但改用新协议类型。`heartbeat.py` 使用明确的连接状态与证据接口，不再依赖 `_client._ws` 等旧库私有结构。runner 的发送和 receipt 匹配原则不变。

## 两类会话的数据隔离

### 匿名展示监听

1. 用独立临时匿名上下文访问目标公开直播页面，获取本次连接所需的房间信息、访客参数和签名环境。
2. 只使用该匿名上下文自动取得的访客状态完成初始 fetch 和 WSS 握手。
3. 不能读取正式账号库或复用已登录浏览器 profile。准备失败时返回安全的监听失败，不降级读取发送账号 Cookie。
4. 访客 Cookie 不写回正式账号库；结束时释放自身 HTTP/WSS 及临时浏览器资源。浏览器只用于获取真实会话状态，不承担被迁移的 frontier 签名计算。

### 登录账号心跳

1. 使用现有私有账号任务传入的当前账号 Cookie、UA 和同会话可用环境材料。
2. 如果签名所需材料不足，明确失败并阻止对应账号后续发送；不混入另一账号或匿名会话的认证环境来凑字段。
3. Cookie 只发往经过校验的 TikTok 目标。WSS 只允许 `wss`、443/默认端口、TikTok 子域及直播协议路径；禁止 URL 用户密码及未经重新校验的重定向。匿名页面/HTTP 请求同样限制目标来源。
4. 签名在本机计算，登录 Cookie 不发送到第三方签名站点，也不放入进程命令行、错误信息或日志。
5. 每个账号 × 直播间有自己的连接、心跳记录和取消范围；不能共享带认证的连接。

## WSS 协议与生命周期

- 使用上游已实现的初始 fetch → cursor → frontier 签名 → WSS → 入房/心跳/ACK 流程，处理二进制帧及 gzip 响应；没有有效房间/游标/签名不得虚报连接成功。
- 心跳单独按单调时钟调度，即使没有业务消息、持续收到消息或 recv 超时，也应按期执行；发送成功才计入已发送次数。
- ACK 回显当前服务端响应要求的 log ID / internal extension，不自造字段、不把聊天内容当 ACK。
- 对帧长、解压后大小、字段边界和评论缓存设置有限上限；畸形包不能无限循环、无限解压或泄漏原始内容。
- 未知事件可忽略；帧无效、连接关闭、持续协议错误、签名失败或房间不匹配需转为可观测的不可用状态，唤醒等待方。
- 账号心跳继续至少预热 30 秒、至少三次目标房间的实际心跳，并确认有效入房响应；保留既有心跳间距和目标一致性要求，不以本地定时器次数伪造证据。
- 账号 WSS 覆盖该任务连续发送和展示确认阶段。发送阶段断开就阻止后续请求，不在后台自动重连后继续发送；不因展示未观察到而补发。
- 展示监听可沿用现有启动重试上限。历史评论与实时评论须区分，避免刚启动取得的历史数据成为新消息展示证据。
- 取消检查覆盖初始化、签名、心跳和等待；只关闭当前任务拥有的资源，不强杀用户浏览器或其他进程。底层网络调用使用有限超时，结束要等自身线程安全退出。
- 监听线程显式继承安全任务上下文，确保 WSS 生命周期日志也带直播间、账号及连接用途。

## 展示核对和日志

保持按消息 ID、发送时间、正文和发送者身份联合核对；归一化上游 chat 事件的字符串用户 ID、用户名、昵称、正文和消息 ID。不能只凭正文或同名用户判定成功。

每条实际完成请求继续产生独立终态记录：`observed`、`not_observed`、`listener_unavailable`、`send_failed`；包括账号短 ID/用户名、目标直播间、序号和可用的数字消息 ID。取消、监听异常或账号元数据保存失败不能丢失已完成请求的结果，不为未发送队列伪造终态。

WSS 日志保留 `delivery_observer` 与 `account_heartbeat` 用途，账号心跳明确显示登录态用途，但不输出 Cookie、签名、storage、完整带查询参数的地址或原始协议 payload。响应预览保持先脱敏、再打印前 150 个字符。未监听到不等于确定未展示；心跳成功不等于账号认证一定有效，也不等于弹幕一定对所有观众可见。

4. 控制时钟验证 30 秒/三心跳/入房证据门槛、空闲心跳、断线停止、取消以及发送/确认期间的连接寿命，不增加聊天 POST。
5. 覆盖消息 ID 大整数保真、历史评论排除、相同正文不同 ID、发送者识别、监听不可用与已完成结果保留，并确认日志归属和脱敏。
6. 回归三个房间并发/后续排队、每房间多账号并发、累计统计、状态合并与 UI 锁定行为；不改变次数、间隔和账号选择。
7. 干净副本全量测试、源码/浏览器隐私扫描、候选 EXE 构建、空账号启动自检、包内 Python 签名源码和依赖核对、无 Node/JS 签名运行器核对、旧版本备份及正式账号哈希核对均通过后交付。
8. 本轮不自动向真实直播间发送测试消息。协议连通性和实际展示需在用户另行指定的测试范围内验证；未经实测不能把离线测试当作真实平台成功证据。
